# 功能实现说明

本版已于 2026-10-08 使用 Anaconda Python 3.11 与 DeepSeek Flash 完成本地验收，覆盖演示项目和 boltons 数学模块。实际结果与证据入口见 README 和 `docs/验收记录.md`。原始 `功能需求.md` 未修改；这里说明实现与边界，不将局部验收扩展为所有项目/环境均已验证。

## CoverUp 复用与扩展

实际提取了 CoverUp 的 segment、codeinfo、utils 源码模块，位于 `src/llm_test_tool/_vendor/coverup/`。`coverage_adapter.py` 将 coverage.py 的行和分支数据转换为 CoverUp 输入，再调用其未覆盖代码分段算法及上下文提取。这部分不是单纯改名或引用仓库。

CoverUp 原有目标主要是提升覆盖率；本版补充需求驱动黑盒、分模式测量、缺陷证据审查、类型修复和验收证据。使用 coverage.py 是为统一 pytest 行/分支数据和执行后报告格式，不依赖上游 SlipCover。源码读取适配 Python 编码声明，原版权及 Apache 许可证保留。

## 功能入口

- 目标与接口约定：`config.py` 校验项目配置；CLI 的 init 命令生成骨架；`examples/boltons-project.json` 及 `boltons-contracts.json` 准备真实开源对象。
- 黑白盒分离：`prompts.py` 形成互不共享对话的两种生成请求；黑盒不接收源码及报错栈；白盒使用 `coverage_adapter.py` 提取未覆盖位置与源码。
- 正常/边界/异常及需求追踪：`validation.py` 校验用例元数据、需求编号、断言与测试模块；`pipeline.py` 记录每个约定在两种方式下的场景覆盖情况。
- 执行与实际结果：`runner.py` 调用独立的 `_worker.py`；pytest hook 收集执行状态、异常、record_property 输入/预期/实际，以及 coverage.py 行/分支数据。错误/不稳定测试不参与有效集。
- 多轮反馈：`pipeline.py` 的 generate_rounds 根据本模式反馈优化用例，白盒附源码/缺失覆盖位置；支持轮数、覆盖目标和停滞阈值，每轮保存指标与 LLM 调用数。
- 复核后补充：supplement 命令针对缺少场景的需求生成替代测试，保存补充阶段的约定与源码指纹；已齐全的方式不再重复生成。初始修复前覆盖率与补充阶段的最终覆盖率分别保留。
- 缺陷分类与证据：`validation.py` 的 validate_assessment 要求接口约定的逐字证据；`pipeline.py` 区分机器确认、人工待审、证据不足、测试错误和环境问题。
- 分类修复：`prompts.py` 的 REPAIR_STRATEGIES 提供四类策略；`repair.py` 限制候选仅修改对应源文件、精确匹配原文、限制规模并保护原接口。
- 严格回归：`repair.py` 保存修复前的连续复现及通过集，对候选连续复测，保护测试数量、文件指纹及原先通过集；失败候选在 finally 中撤回，只保留验证通过候选在工作副本中。
- 报告及分类统计：`report.py` 生成离线 HTML、JSON、Markdown，展示原有/黑盒/白盒/合并/回归测试覆盖率、缺失位置、每轮指标、用例证据和分类修复尝试通过率；所有 HTML 动态内容转义。
- LLM 配置与预算：`llm.py` 使用标准库 HTTP 客户端访问 `.env` 指定的兼容接口，记录各次请求，限制次数和 Token 预算，拒绝接口重定向，继续修复不会覆盖已记录调用。

## 首版边界

仅支持 Python 3.11+、pytest、同步测试模块和兼容 Chat Completions 的 LLM。异步接口可在同步用例中使用 asyncio.run；复杂 pytest 插件需要显式配置。覆盖率测量只计配置选定的源码文件，不代表全部仓库的覆盖率；未实现 subprocess/multiprocessing 覆盖合并。

默认配置支持关闭网络、只读源码和资源限制的 Docker 容器；本次实际验证的是 Anaconda 本地模式，Docker 路径尚未验证。本地模式只提供副本和完整性检查。依赖声明通过安装检查，本次未进行依赖漏洞扫描。

机器确认与回归通过都不是软件绝对正确的证明。错误约定会导致错误测试或错误修复，真实开源验收前应复核接口解释；若指定 manual 策略，只对人工确认候选自动修复。可能保留同一根因的多个候选记录，统计按候选记录计数。

运行时使用原项目副本，不自动合入原仓库。新生成使用新运行目录；已确认缺陷支持继续 repair，复核后支持 supplement 补充场景，暂不支持从中断的半轮精确恢复。排除用例后，旧覆盖率会标记过期，下一次执行后更新。复核记录区分 human 和 assistant 来源，助手复核不会标为人工确认。

## 已执行的验收与剩余边界

连接检查、演示项目、未经人工注入缺陷的 boltons 目标均已实际运行。证据核对覆盖黑白盒请求分离、场景标注、覆盖率集合、原文件指纹、复现前后和回归结果、补丁一致性及密钥未写入产物。另有 11 项确定性测试验证回归失败撤回、补丁保护、循环执行记录和报告处理。真实运行包含模型错误用例与错误分类，复核排除后补齐了场景，不能将这些候选算作真实缺陷；boltons 的位宽发现仍以本地约定为依据，尚无上游确认。

Docker、多语言、复杂第三方目标、网络故障恢复及其他模型未纳入本次验收。实际运行只观察到边界与空序列异常处理的缺陷修复，其余分类策略没有真实缺陷样本的验证结论。

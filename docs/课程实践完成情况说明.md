整理日期：2026-10-26。实验数据来自 2026-10-08 保存的验收记录；2026-10-24 梳理项目时另行运行了工具自身的测试，11 项全部通过。

## 一、总体判断

结合题目要求、项目代码和已有运行报告，目前已经完成了可运行的课程实践版本。基础验收项都有对应实现和证据，覆盖率对比、缺陷自动修复两个加分方向也已落地。当前主要需要整理汇报材料、明确实验范围，而不是从头补核心功能。

课程题目为“LLM 辅助软件测试工具”，要求为真实开源小项目自动生成测试用例、覆盖正常／边界／异常场景，并提交缺陷清单与验证记录。项目本地的《功能需求.md》进一步细化了黑盒与白盒测试、分类修复、多轮反馈和回归验证要求。

## 二、对照题目的完成程度

### 1. 选择真实开源小项目：已完成

选择的是 Python 开源工具库 boltons 25.0.0，具体测试范围为 `mathutils.py` 中的 `clamp`、`ceil`、`floor` 和 `Bits`。版本固定，保留了原始源码、许可证和原有测试。

成果针对选定数学模块，不能扩展为整个 boltons 仓库。

### 2. LLM 自动生成单元测试：已完成并实测

已接入 DeepSeek，能够生成 pytest 测试，并自动执行、保存结果。boltons 实验累计生成 48 个测试模块，复核排除 7 个错误用例，最终保留 41 个有效生成测试。

### 3. 正常、边界、异常场景：已有覆盖记录

项目区分黑盒和白盒。四个目标接口在两种测试方式下，都保存了正常、边界、异常场景记录，以及需求编号、输入、预期和实际结果。

### 4. 缺陷清单与验证记录：已完成

已保存候选缺陷、判断依据、复现结果、修复差异和回归记录，也明确记录了哪些失败其实来自错误测试。

### 5. 覆盖率对比报告：加分项已完成

同时测量原有测试、黑盒、白盒、黑白盒合并及完整回归的行覆盖率和分支覆盖率。

### 6. 缺陷自动修复：加分项已实现，有成功样例

已实现分类、生成补丁、修复前后验证、回归检查和失败补丁撤回。真实项目保留了一项边界发现的成功修复证据，但尚不能证明所有缺陷类型都能稳定自动修复。

## 三、目前具体做了哪些工作

项目已经形成以下完整流程：

**配置目标及接口约定 → LLM 生成测试 → 执行与测量覆盖率 → 反馈后补充测试 → 审查失败原因 → 分类修复 → 回归验证 → 输出报告。**

### 项目接入与配置

支持配置源码目录、原有测试、接口约定、迭代轮数、覆盖率目标和调用预算，也能生成新项目的配置骨架。

### 黑白盒生成分离

黑盒依据需求、签名和接口约定生成；白盒读取源码，利用 CoverUp 的代码分段和上下文提取能力，针对未覆盖行、分支补充用例。

### 多轮执行反馈

生成后实际运行测试，将执行结果反馈给模型，支持按轮数、覆盖目标或连续无提升停止。

### 失败审查与分类修复

区分程序缺陷、测试错误、环境问题和证据不足；为边界、空值或类型、异常处理、逻辑错误设置不同修复策略。

### 回归验证与证据留存

只有复现测试修复前失败、修复后通过，而且原先通过的测试继续通过，才保留补丁。修改发生在工作副本中，不自动改写原始目标项目。

### 报告与复核工具

输出 HTML、JSON、Markdown，保留模型调用、生成代码、每次执行、覆盖率、补丁及复核决定。

各项实现的代码入口对应关系见[功能实现说明](功能实现说明.md)。

## 四、已有实验结果

### 1. 真实开源目标 boltons

- 有效生成测试：黑盒 21 个、白盒 20 个。
- 加上原有 11 个测试，最终回归 52/52 通过。
- 最终行覆盖率／分支覆盖率：
  - 原有测试：84.96%／68%。
  - 黑盒测试：72.57%／70%。
  - 白盒测试：93.81%／86%。
  - 黑白盒合并：98.23%／94%。
  - 加入原有测试的完整回归：99.12%／96%。

两种生成方式具有互补效果：合并测试覆盖到了各自单独运行时遗漏的位置。合并覆盖率来自实际执行，不是两个百分比的平均。以上覆盖率仅针对选定的 mathutils 模块。

### 2. 保留的边界发现与修复

`Bits(4, 2)` 接受了无法用两位表示的数值 4。按照本地声明的固定位宽约定，应抛出异常。最终补丁将上界判断从 `>` 改成 `>=`，并保存了修复前连续失败、修复后连续通过以及回归通过的证据。

**这项发现依据本地接口约定确认，尚未获得上游维护者确认。** 实验中的其他错误索引、前导零等候选已排除，不能计为真实软件缺陷。

### 3. 教学演示项目

另有一个教学演示项目，成功修复了两个人工注入的问题，最终 24/24 通过，行和分支覆盖率均为 100%。

该样例证明流程可以跑通，但不能替代真实开源项目的发现成果。

### 4. 工具自身测试

2026-10-24 梳理时重新运行：

```powershell
python -m pytest tests -q -p no:cacheprovider
```

结果为 11 passed。该测试验证工具规则，不等于重新调用模型运行整套目标项目实验。

## 五、课程提交与答辩时需要说明的边界

### 复核参与情况

boltons 实验经过助手复核、错误用例排除和补充生成，最终结果不能描述成完全无人干预的一次运行。

### 能力验证范围

当前实测的是 Python、pytest、本地执行和 DeepSeek；Docker 路径、其他模型、复杂依赖项目尚未验收。四类修复策略都有代码，但成功样例主要涉及边界和空序列异常处理。

### 覆盖率提升的解释

最终数据同时受到多轮生成、补充测试及源码修复影响，不能直接当作严格控制变量下的模型能力对比。

### 提交证据的保留

`runs/` 被 Git 忽略，交作业时需要单独打包报告、生成测试、补丁和执行记录。
